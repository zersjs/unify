# Threat model

**Assets:** keyboard and mouse control (equivalent to remote code execution), clipboard content (passwords, personal data), device private keys.

**Trust boundaries:**

1. Local network ↔ Unify listener (untrusted traffic).
2. Paired device ↔ this computer's input system (only after an explicit control hand-over).
3. Unify process ↔ OS secret store.
4. Web UI ↔ Rust back end (Tauri commands).

## Abuse cases and mitigations

| Scenario | Mitigation | Code / evidence |
|---|---|---|
| Someone on the same network connects to the port and sends keystrokes | TLS 1.3 required; client certificate required; a `Hello` not matching the pinned peer is rejected; any message before authentication closes the connection | `session.rs::on_hello`, `on_conn_message`; tests `unpaired_certificate_is_rejected_after_hello`, `unauthenticated_input_before_hello_closes_connection` |
| Guessing the pairing code | SPAKE2: the code is never sent, offline guessing is impossible; one guess per connection; the window closes after 5 failures; the code lives 120 s | `pairing.rs`; test `wrong_pairing_code_is_rejected_without_pairing` |
| Man in the middle during pairing | Confirmation MACs bound to the TLS exporter and both certificate fingerprints; an attacker running two TLS sessions cannot pass; the code-generating computer also shows the fingerprint and asks for approval | `pairing.rs` tests `different_channel_binding_fails_confirmation`, `swapped_fingerprints_fail_confirmation` |
| Replay | TLS 1.3 record sequence numbers; 0-RTT and session tickets disabled | `tls.rs` |
| Paired device sends unwanted input | Input applied only after `Enter` was accepted; `Enter` refused when input sharing is off | `control.rs::on_remote_input`; tests `input_from_peer_is_ignored_unless_control_was_granted`, `peer_with_input_sharing_disabled_refuses_control` |
| Key stuck down after a disconnect | The controlled side tracks held keys/buttons and releases them on disconnect, `Release` and return | `PressedState`; test `connection_loss_releases_keys_held_on_controlled_machine` |
| Password manager content leaking | Content flagged with `ExcludeClipboardContentFromMonitorProcessing`, `Clipboard Viewer Ignore`, `CanIncludeInClipboardHistory=0`, `org.nspasteboard.ConcealedType/TransientType/AutoGeneratedType` is not sent | `windows/clipboard.rs`, `macos/clipboard.rs`; test `concealed_clipboard_content_is_never_sent` |
| Data leaking through logs | Clipboard text, key codes and keys are never logged at any level; rejected connections log only IP and short fingerprint | `tracing` call sites |
| Reading the private key from disk | Key in Keychain / Credential Manager; only the public certificate on disk | `keystore.rs`, `identity.rs` |
| Oversized or malformed packets | Frame ≤ 64 KiB, clipboard ≤ 16 MiB, chunk ≤ 16 KiB, order/length/hash validation, length and control-character limits on strings | `frame.rs`, `message.rs`, `clipboard.rs` |
| Connection flood | At most 8 concurrent handshakes; 5 s handshake and 10 s `Hello` timeouts | `session.rs` |
| Content injected into the web UI | Strict CSP (`script-src 'self'`), frozen prototypes, event-listen-only capability; length limits on command arguments | `tauri.conf.json`, `capabilities/default.json`, `commands.rs` |
| Compromised peer | Remove the pairing or reset the device identity: the old certificate is rejected immediately | `remove_peer`, `reset_identity`; test `removing_peer_disconnects_and_rejects_further_sessions` |

## Out of scope

- Malware running in the same user session (it can call the same APIs anyway).
- Lock screen, UAC secure desktop and elevated windows: the OS blocks synthetic input; Unify does not try to bypass this.
- mDNS records are unauthenticated; they are used only as address hints, trust decisions come from TLS pinning.
